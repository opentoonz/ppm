# 共有フォルダでの運用

PPM は、進捗をデータベースではなく、ファイルで管理します。PPM 専用のサーバーやデータベースを用意する必要はありません。
各 PC の PPM が、ファイルサーバーや NAS の共有フォルダにある同じファイルを直接読み書きすることで、スタジオの全員が進捗を共有します（[進捗はファイルで管理される](../concepts/progress-files.ja.md) を参照）。
このページでは、そのための構成と、複数人で使うときの注意をまとめます。

## 推奨する構成

### 共有フォルダに置くもの

次のフォルダは、すべて共有フォルダに置き、PPM を使う全員が同じものを見るようにします。

| フォルダ | 設定する場所 |
|---|---|
| Stuff フォルダ | 各 PC の `conf.ini`（[Stuff フォルダ](stuff-folder.ja.md) を参照） |
| ルートフォルダ（カットのファイル） | プロジェクト設定の **基本情報** |
| プロジェクト情報フォルダ（進捗情報用フォルダ） | 同上 |
| ログフォルダ（履歴のルートフォルダ） | 同上 |

構成の例です。

```
\\fileserver\anime\
├─ PPM\
│  └─ stuff\                 … Stuff フォルダ
│     ├─ projects\
│     ├─ loc\
│     └─ rename_scripts\
└─ my_title\
   ├─ cuts\                  … ルートフォルダ
   └─ PPM\
      ├─ info\               … プロジェクト情報フォルダ
      └─ log\                … ログフォルダ
```

### Stuff フォルダを共有する

各端末の `conf.ini` で、同じ Stuff フォルダを指定します。上の構成では、プロジェクトのルートを `../../my_title/cuts`、プロジェクト情報を `../../my_title/PPM/info`、ログを `../../my_title/PPM/log` にします。どちらの OS でも Stuff フォルダが起点になるため、Mac のマウント先が `/Volumes/anime-1` でも同じ設定を使えます。

絶対パスを使う場合、Windows では UNC パスにするとドライブ文字の違いを避けられます。プロジェクトに `//fileserver/anime` を保存している場合、Mac では `/Volumes/anime`、ドライブ文字でアクセスする PC では `Y:/` に割り当てます。既存プロジェクトの `Z:/` を別の PC の `Y:/` に割り当てることもできます。Mac のみのスタジオではマウント先をそのまま保存できます。対応表と既定値ファイルの例は[環境設定](../using/preferences.ja.md)を参照してください。

### ファイル名、ZIP、ログ

Windows でも作成できる名前を使います。`< > : " / \ | ? *`、末尾のピリオドや空白、`CON` や `NUL` などの予約名は避けてください。大文字小文字だけが違う名前や、濁点などの合成・分解だけが違う名前も避けます。大文字小文字を区別するかどうかは共有先によって異なります。コピー時に正規化すると同じ名前になる項目が複数見つかった場合は、名前を整理してからやり直してください。

フォルダをコピーするときは、Finder の `.DS_Store` と AppleDouble の `._*` ファイルを除外します。コピー後に誰かが作画ファイルなどを追加したフォルダは、取り消しても残ります。Windows と macOS では ZIP を作成するツールが異なります。受け渡しの際は、受け取り側の解凍ソフトで日本語の名前や内容を確認してください。操作ログには OS のログイン名が記録されます。環境設定の「ユーザー名」で指定するのは、パスの `[USER_NAME]` マクロに代入する名前です。

### PPM 本体をどこに置くか

PPM 本体（`ppm.exe` のあるフォルダ）は、各 PC に置いても、共有フォルダに置いてもかまいません。

| 置き場所 | よい点 | 気をつけること |
|---|---|---|
| 各 PC（例：`C:\Tools\PPM`） | 起動が速い。サーバーが止まっても PPM 自体は起動できる。 | 各 PC の `conf.ini` に、共有の Stuff フォルダを書きます。PPM を新しくするときは、全員の PC で入れ替えます。 |
| 共有フォルダ | 全員が必ず同じバージョンを使う。`conf.ini` も1つで済む。 | PPM を新しくするときは、全員に PPM を終了してもらう必要があります（使用中の `ppm.exe` は上書きできません）。 |

どちらの場合も、**全員が同じバージョンの PPM を使う**ようにしてください。
バージョンが混ざると、新しいバージョンで保存したプロジェクトの設定を、古いバージョンが正しく読めないことがあります。

## 複数人での同時利用

### アクションの実行

別々のカットであれば、何人が同時にアクションを実行してもかまいません。

- ほかの人が実行したアクションは、自分の一覧には自動では反映されません。**リスト更新** を押すと反映されます（[カットがリストに並ぶ条件](../using/scene-list.ja.md) を参照）。
- 同じカットに、2人がほぼ同時にアクションを実行すると、後から実行した方は、ファイルがすでに移動されているためにステップが失敗することがあります。失敗したときは、**リスト更新** を押して、カットが今どの工程にいるかを確かめてください（[カットが工程を流れる仕組み](../concepts/scene-flow.ja.md) の「失敗したとき」を参照）。
- 確認画面を開いている間に、ほかの人が同じカットを進めることもあります。確認画面を開いたまま長く置かないようにしてください。

工程ごとのカットの一覧（`progress_cache` フォルダのファイル）は、書き換えている間だけ、ほかの人が同時に書き換えないように保護されます。
そのときに、同じフォルダに `〜_details.lock` というファイルが一時的に作られます。
PPM が強制終了したときなどに残ることがありますが、しばらくすると PPM はそれを無視して処理を続けます。

### プロジェクト設定の変更

プロジェクト設定は、ほかの人の PPM にはすぐには反映されません。
PPM は、プロジェクトのファイルを **起動したときと、プロジェクトを切り替えたとき** にだけ読み込みます。

- プロジェクト設定を保存したら、スタッフに PPM を起動し直してもらってください。新しく作ったプロジェクトも、起動し直すと **プロジェクトID** の一覧に並びます。
- プロジェクト設定を編集するのは、一度に1人にしてください。PPM は、ほかの人が同時に編集していることを知らせません。ほかの人が先に保存していた場合は、保存するときに警告が表示されますが、そのまま保存すると、後から保存した人の内容でファイル全体が上書きされます（[プロジェクトの保存とテスト](../designing/saving-and-testing.ja.md) を参照）。
- 編集を始める前に、PPM を起動し直してください。古い設定を読み込んだままの PPM でプロジェクト設定を開いて保存すると、その間にほかの人が保存した変更が消えてしまいます。

制作の途中で設定を変えるときの注意は、[運用中に設計を変えるときの注意](../designing/changing-in-production.ja.md) を参照してください。

### Stuff フォルダの中のファイル

| ファイル | 反映されるとき |
|---|---|
| プロジェクトのファイル（`projects`） | PPM を起動したとき、プロジェクトを切り替えたとき |
| 翻訳ファイル（`loc`）、`defaultusersettings.ini` | PPM を起動したとき |
| リネームスクリプト（`rename_scripts`） | スクリプトを使うアクションを実行するたび |

## アクセス権

共有フォルダには、次のアクセス権を設定します。

| フォルダ | PPM を使う全員 | プロジェクトの設計者 |
|---|---|---|
| ルートフォルダ | 読み書き（削除を含む） | 読み書き（削除を含む） |
| プロジェクト情報フォルダ | 読み書き（削除を含む） | 読み書き（削除を含む） |
| ログフォルダ | 読み書き（削除を含む） | 読み書き（削除を含む） |
| Stuff フォルダ（上の3つを除く） | 読み取り | 読み書き |

- アクションは、カットのファイルの名前を変えたり、移動したり、消したりします。ルートフォルダとプロジェクト情報フォルダには、Windows のアクセス許可でいう「変更」（削除を含む）の権限が必要です。
- ログフォルダには、カットのログのほかに、Google スプレッドシート連携や Google Chat 通知の記録も書き込まれます。スプレッドシートへの書き込みの記録は、成功すると消されるので、ログフォルダにも削除の権限が必要です（[Google スプレッドシート連携](../integrations/google-spreadsheet.ja.md)、[Google Chat 通知](../integrations/google-chat.ja.md) を参照）。
- ルートフォルダ、プロジェクト情報フォルダ、ログフォルダを相対パスで指定すると、Stuff フォルダの中に置かれます（サンプルプロジェクトの `sample_data` など）。その場合も、それらのフォルダには上の3行の権限を設定してください。
- Stuff フォルダを設計者だけが書き込めるようにすると、スタッフがうっかりプロジェクト設定を変えてしまうことを防げます。書き込めない人がプロジェクト設定を保存しようとすると、エラーのメッセージが表示され、保存されません。
- `rename_scripts` フォルダがないときは、PPM が作ってサンプルのスクリプトを置こうとします。Stuff フォルダを読み取りだけにする場合は、先に `rename_scripts` フォルダを作っておいてください。

## 共有フォルダの場所を移す

サーバーを入れ替えるときなど、共有フォルダの場所を移すときは、次の順に作業します。

1. 全員に PPM を終了してもらいます。
2. Stuff フォルダ、ルートフォルダ、プロジェクト情報フォルダ、ログフォルダを、中の構成を変えずに新しい場所へコピーします。
3. 各 PC の `conf.ini`（PPM 本体を共有している場合は1つ）の `StuffFolderPath` を、新しい Stuff フォルダに書き換えます。
4. PPM を起動し、プロジェクト設定の **基本情報** で、ルートフォルダ、進捗情報用フォルダ、履歴のルートフォルダを新しい場所に書き換えます。相対パスで書いているものは、そのままでかまいません。
5. **パスマクロ** や工程の条件パス、ステップのパスに、古いサーバーの名前を直接書いているところがあれば、書き換えます。
6. 保存して、いくつかのカットで一覧の表示とアクションの実行を確かめます（[プロジェクトの保存とテスト](../designing/saving-and-testing.ja.md) を参照）。
7. 問題がなければ、全員に PPM を起動してもらいます。古い場所のファイルは、しばらく残しておくと安心です。

プロジェクト情報フォルダとログフォルダの中のファイルには、パスは書かれていません。
フォルダごと移せば、そのまま使えます。
