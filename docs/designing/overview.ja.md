# 設計の流れと事前準備

この章では、作品の工程やファイルの命名規則を PPM の**プロジェクト**として組み立てる方法を説明します。
読者は、パイプライン設計者（作品の工程を決め、PPM のプロジェクトを作る人）を想定しています。

先に [PPMの仕組み](../concepts/glossary.ja.md) の章を読んで、工程・工程グループ・キューファイル・条件パスなどの用語を確かめておいてください。

## 設計の流れ

プロジェクトは、次の順に組み立てると進めやすくなります。

1. **今のやり方を洗い出す**：工程、担当、ファイルの名前と置き場所の決まりを書き出します（下の「既存のパイプラインを洗い出す」）。
2. **[基本情報](basics.ja.md)**：プロジェクトの名前、カット番号の接頭辞、データを置くフォルダを決めます。
3. **[パスマクロ](path-macros.ja.md)**：工程グループごとのカットフォルダの場所を、マクロとして登録します。
4. **[工程グループ](workflow-groups.ja.md)**：LO、原画、動画のような工程のまとまりを作ります。
5. **[カット情報](info-tags.ja.md)**：「バンク」のような、カットに付ける印を用意します（必要な場合）。
6. **[工程を設計する](workflows.ja.md)**：工程と、その条件パス、アクション、ステップを組み立てます。
7. **[プロジェクトの保存とテスト](saving-and-testing.ja.md)**：保存して、テスト用のカットで一通り動かします。

はじめから全部を作る必要はありません。
サンプルプロジェクトを元に、自分たちの作品に合わせて書き換えていくのが近道です（下の「新しいプロジェクトを作る」を参照）。

## 既存のパイプラインを洗い出す

PPM は、今スタジオで行っている「ファイルの名前と場所による受け渡し」を、そのまま写し取る道具です。
新しい運用を考えるより先に、今のやり方を表にしてみてください。

| 書き出すこと | 例（サンプルプロジェクトの LO） |
|---|---|
| 工程グループ | LO、原画、動画、仕上 |
| 工程と、その順番 | 演出チェック → 監督チェック → 作監チェック → 演助チェック → LO上がり |
| 各工程の担当 | 演出、監督、作監、演助 |
| 各工程にいるときのファイル（名前と場所） | `c0001_LO_ej_s_k_e.clip`（演出チェック）、`c0001_LO_ej_s_k.clip`（監督チェック）… |
| 次の工程に渡すときにすること | 末尾の記号を1つ取るリネーム |
| 次の工程グループに渡すときにすること | 原画のフォルダに目印のファイルを置く |

サンプルプロジェクトでは、まだチェックしていない人の記号（`_e` 演出、`_k` 監督、`_s` 作監、`_ej` 演助）をファイル名の末尾に並べておき、チェックが済むたびに末尾から1つずつ取っていきます。
工程の見分け方は、ファイル名でなくてもかまいません。
スタジオによっては、チェックの担当ごとにフォルダを分け、カットフォルダをフォルダごと移動して受け渡しているところもあります。

```
[ROOT]/01_genga/kantoku/c0001/   … 監督がチェックするカット
[ROOT]/01_genga/sakkan/c0001/    … 作監がチェックするカット
```

この場合、カットフォルダの中のファイル名は変わらず、工程ごとに変わるのは途中のフォルダの名前です。
PPM の条件パスは、ファイル名だけでなく、途中のフォルダを含めた**パス全体**で判断するので、このようなやり方もそのまま写し取れます（例：`[ROOT]/01_genga/kantoku/[PREFIX][CUTNUMBER]/[PREFIX][CUTNUMBER]_genga.clip`）。
カットフォルダの移動は、「フォルダ内容をコピー」ステップの **転送** を「移動」にして行えます。

大切なのは、**ファイルのパス（名前と場所）を見れば、今どの工程にいるかがわかる**決まりがあることです。
そのような決まりがあれば、そのまま PPM の条件パスにできます。

決まりがはっきりしていない場合は、この機会に決めておきます。
1つの工程グループの中で、工程ごとに、キューファイルのパス（ファイル名か、途中のフォルダの名前）が必ず違うようにしてください。
同じファイルが2つの工程の条件パスに当てはまると、カットが両方の工程に並んでしまいます。

## フォルダ構成を決める

カットのファイルを置くフォルダの構成も決めておきます。
PPM は、プロジェクトの**ルートフォルダ**（`[ROOT]`）の中に、工程グループごとのカットフォルダがある、という形を前提にしています。

サンプルプロジェクトでは、次のような構成です。

```
sample_data/                     … ルートフォルダ [ROOT]
├─ 01_LO_genga/
│  └─ 00/                        … シークエンス [SEQUENCE]
│     └─ c0001/                  … 接頭辞とカット番号 [PREFIX][CUTNUMBER]
│        ├─ LO/                  … LO のカットフォルダ
│        └─ genga/               … 原画のカットフォルダ
├─ 02_douga/
│  └─ 00/
│     └─ c0001/                  … 動画のカットフォルダ
├─ 04_shiage/
│  └─ 00/
│     └─ c0001/                  … 仕上のカットフォルダ
└─ PPM/
   ├─ info/                      … プロジェクト情報フォルダ
   └─ log/                       … ログフォルダ
```

決めておくことは、次のとおりです。

- 各工程グループのカットフォルダの場所（[パスマクロ](path-macros.ja.md) で登録します）
- 100カットごとのフォルダ（シークエンス）に分けるかどうか（[基本情報](basics.ja.md) の「100カットごとにまとめる」）
- 話数ごとにフォルダを分けるかどうか（TV シリーズなど。[基本情報](basics.ja.md) の「話数あり」）
- リテイクのとき、テイク番号の付いたカットフォルダ（`c0001_t02` など）をどこに作るか（[工程グループ](workflow-groups.ja.md) を参照）
- プロジェクト情報フォルダとログフォルダの場所

これらのフォルダはすべて、PPM を使う全員が読み書きできる共有フォルダに置きます（[共有フォルダでの運用](../administration/shared-operation.ja.md) を参照）。

## プロジェクト設定ダイアログを開く

プロジェクトの設計は、**プロジェクト設定** のダイアログで行います。

1. メイン画面の上部で、設計したいプロジェクトを選びます。
2. macOS ではメニューバーから **プロジェクト → プロジェクト設定 → 基本情報** を選びます。Windows では歯車ボタンから **プロジェクト設定** を選びます。

![プロジェクト設定ダイアログ](../images/ja/designing/project-settings-dialog.png)

ダイアログの左側には、設定のカテゴリが並んでいます。

| カテゴリ | 内容 |
|---|---|
| **基本情報** | プロジェクト名、接頭辞、フォルダの場所、話数など（[基本情報](basics.ja.md)） |
| **パスマクロ** | パスの中で使うマクロ（[パスマクロ](path-macros.ja.md)） |
| **工程グループ** | 工程グループの一覧（[工程グループ](workflow-groups.ja.md)） |
| **カット情報** | カットに付ける印（[カット情報](info-tags.ja.md)） |
| **工程 - 一覧表示** | 工程を、一覧の形で編集します（[工程を設計する](workflows.ja.md)） |
| **工程 - フローチャート表示** | 工程を、フローチャートの形で編集します（[工程を設計する](workflows.ja.md)） |

左下には、**プロジェクトID** の欄と、**保存する**・**閉じる** ボタンがあります。
プロジェクトIDは、プロジェクトのファイル名（`sample_project.ppmprj` の `sample_project` の部分）で、メイン画面の「プロジェクトID：」の欄に表示される名前です。
ダイアログのタイトルには、「プロジェクト： プロジェクト名 ( プロジェクトID.ppmprj )」と表示されます。

設定を変えても、**保存する** を押すまでプロジェクトのファイルには書き込まれません。
保存していない変更があるときは、タイトルの末尾に `*` が付きます。
保存の方法は [プロジェクトの保存とテスト](saving-and-testing.ja.md) で説明します。

### 新しいプロジェクトを作る

新しいプロジェクトは、今あるプロジェクトを別のプロジェクトIDで保存して作ります。

1. 元にするプロジェクト（サンプルプロジェクトなど）を選んで、**プロジェクト設定** を開きます。
2. 左下の **プロジェクトID** の欄に、新しいプロジェクトIDを入れます（例：`my_title`）。
3. **保存する** を押します。

元のプロジェクトはそのまま残り、同じ内容の新しいプロジェクトのファイルが作られます。
ダイアログを閉じると、メイン画面は新しいプロジェクトに切り替わります。
そのあと、新しいプロジェクトの **基本情報** で、フォルダの場所などを書き換えていきます。

> **注意**：フォルダの場所を書き換える前のプロジェクトは、元のプロジェクトと同じフォルダを見ています。
> 新しいプロジェクトでアクションを実行する前に、ルートフォルダ、プロジェクト情報フォルダ、ログフォルダを、新しいプロジェクト用のものに変えてください。
