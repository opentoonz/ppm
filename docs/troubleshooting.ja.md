# トラブルシューティング / FAQ

困ったときに、症状から対処を探すためのページです。
くわしい説明は、各項目から案内するページにあります。

まず、次のことを試してください。多くの場合、これで原因がわかります。

- **リスト更新** を押す：ほかの人が進めたカットや、アクションを実行して灰色になった行が、今の状態に更新されます。
- **カット検索** でカットを調べる：カットが所属している工程グループ、今いる工程、テイク、カット情報、ログがまとめて表示されます（[メイン画面](using/main-window.ja.md) を参照）。
- **カットフォルダを開く** でファイルを見る：PPM は、ファイルの名前と場所で進捗を判断しています。カットフォルダにどのファイルがあるかを見ると、PPM の表示の理由がわかります。

## 起動したとき

| 症状 | 原因と対処 |
|---|---|
| **プロジェクトID** の一覧が空で、何も表示されない | PPM が Stuff フォルダを見つけられていません。`ppm.exe` と同じフォルダにある `conf.ini` の `StuffFolderPath` を確かめてください。バックスラッシュ（`\`）を使う場合は、`\\` のように2つ重ねて書きます（[インストール](getting-started/installation.ja.md) を参照）。Stuff フォルダを共有フォルダに置いている場合は、エクスプローラーでそのフォルダを開けるかも確かめます。 |
| 使いたいプロジェクトが **プロジェクトID** の一覧にない | Stuff フォルダの `projects` に、そのプロジェクトのファイル（`.ppmprj`）があるか確かめてください。ほかの人が新しく作ったプロジェクトは、PPM を起動し直すと一覧に並びます。 |
| 「警告： 翻訳ファイルが見つかりません」と表示され、画面が英語になる | 環境設定で選んだ言語の翻訳ファイルが、Stuff フォルダの `loc` フォルダにありません。警告に表示されたパスにファイルがあるか確かめてください（[UI の言語と翻訳ファイル](administration/translations.ja.md) を参照）。 |
| 「警告： TVPaintのバイナリが見つかりません」などと表示される | 環境設定でインストール済みのアプリを選び直します。パスを空欄にすると、その拡張子に OS で関連付けられたアプリを使います。[環境設定](using/preferences.ja.md) を参照してください。 |

## カットがリストに出てこない

カットが一覧に並ぶ条件と、確かめる順番は、[カットがリストに並ぶ条件](using/scene-list.ja.md) にまとめています。
よくある原因は、次のとおりです。

| 症状 | 原因と対処 |
|---|---|
| どの工程にも並ばない | カットが工程グループに所属していません。**カット検索** の「工程グループ」を確かめ、空なら [カットの登録](using/registering-scenes.ja.md) で登録します。 |
| カット検索で「検索されたカットは見つかりませんでした。」と表示される | カットが工程グループに所属しておらず、ログもありません。カット名の打ち間違いがないかも確かめてください。 |
| ファイルを手で置いた、または名前を変えたのに並ばない | ファイル名が工程の条件パスに合っているか確かめます（工程にマウスを重ねると、条件パスが表示されます）。合っていれば、工程グループの更新ボタン（回転矢印のアイコン）を押します（[ファイルを直接扱う](concepts/working-with-files.ja.md) を参照）。 |
| ほかの人が進めたはずのカットが、前の工程に残っている | **リスト更新** を押します。ほかの人の操作は、自動では反映されません。 |
| 同じカットが2つの工程に並ぶ | 前の工程のキューファイルが残っています。カットフォルダを開いて、不要なファイルを消すか、名前を変えます。 |
| 話数を使うプロジェクトで並ばない | 上部の **話数** で、正しい話数を選んでいるか確かめます。 |
| 一覧に何も並ばない | 左側で、その工程のチェックボックスがオンになっているか確かめます（[メイン画面](using/main-window.ja.md) を参照）。 |
| 制作の途中でプロジェクト設定を変えたら、カットが並ばなくなった | 条件パスやフォルダの場所を変えると、すでにあるファイルが見つからなくなります（[運用中に設計を変えるときの注意](designing/changing-in-production.ja.md) を参照）。 |
| サムネイルが表示されない | プロジェクト設定の「カットサムネイルのパス」に合う場所に、画像があるか確かめます（[基本情報](designing/basics.ja.md) を参照）。 |

## ファイルが開かない

| 症状 | 原因と対処 |
|---|---|
| **開く** を押しても、アプリが起動しない | 環境設定でアプリのパスを確かめます。空欄の場合は、エクスプローラーまたは Finder でファイルをダブルクリックし、関連付けられたアプリで開けるか確かめます。指定したアプリを起動できなかったときは、アプリのパスと開こうとしたファイルが表示されます。[環境設定](using/preferences.ja.md) を参照してください。 |
| OpenToonz で開かない | **OpenToonz起動時の引数** を設定している場合は、OpenToonz の起動オプションとして正しいか確かめます。いったん空欄にして開けるなら、引数が原因です。 |
| **開く** を押すと、ファイルではなくカットフォルダが開く | キューファイルが `.clip`、`.tvpp`、`.tnz` 以外（目印のテキストファイルなど）の場合は、カットフォルダを開くのが正しい動きです（[カットに対する操作](using/scene-operations.ja.md) を参照）。 |
| **タイムシートを開く** が押せない | タイムシートが見つかりません。PPM は、工程グループの「XDTS ファイル名」に合うファイルを、標準カットフォルダの中で探します。ファイルの名前と場所を確かめてください（[工程グループ](designing/workflow-groups.ja.md) を参照）。 |
| **ログを見る** が押せない | そのカットのログがまだありません。アクションやカット登録を一度も行っていないカットです。 |
| カットフォルダが開かない | 共有フォルダに接続できているか、エクスプローラーで確かめてください。 |

## アクションが失敗する

アクションのステップが途中で失敗すると、次の警告が表示されます。

> 以下のカットのアクションは失敗又は中断されました。"Show Details"ボタンを押してログをご確認ください。
> 手作業でファイルを確認、修正する必要があるかもしれません。

次の手順で対処します。

1. **Show Details...** を押して、どのカットの、どのステップで止まったかを確かめます。
2. **カットフォルダを開く** を押して、ファイルの状態を確かめます。
   失敗する前に実行されたステップは、元に戻っていません。
3. 原因を取り除いてから、ファイルを手で直すか、**リスト更新** を押してからアクションをやり直します。

失敗は、カットのログに `[失敗]` を付けて記録されます。
**Show Details...** の内容はログには残らないので、必要なら控えておいてください。
仕組みは [カットが工程を流れる仕組み](concepts/scene-flow.ja.md) の「失敗したとき」で説明しています。

よくある原因は、次のとおりです。

| 原因 | 対処 |
|---|---|
| ファイルを作業用のアプリで開いたままにしている | ファイルを保存して閉じてから、やり直します（[ファイルを直接扱う](concepts/working-with-files.ja.md) を参照）。 |
| リネーム先やコピー先に、同じ名前のファイルがすでにある | 古いファイルが残っていないか、カットフォルダを確かめます。 |
| ほかの人が、同じカットを先に進めた | **リスト更新** を押して、カットが今どの工程にいるかを確かめます（[共有フォルダでの運用](administration/shared-operation.ja.md) を参照）。 |
| 共有フォルダに接続できない、または書き込みの権限がない | エクスプローラーで、そのフォルダにファイルを作れるか確かめます。権限は導入担当者に相談してください（[共有フォルダでの運用](administration/shared-operation.ja.md) の「アクセス権」を参照）。 |
| コピー元のファイルやフォルダがない | 確認画面で、警告のアイコンが付いたステップがないかを、**OK** を押す前に確かめてください。 |

### 取り消しが失敗したとき

**取り消す** が途中で失敗した場合も、同じような警告が表示されます（「アクションの取り消しに失敗又は中断されました。」）。
ログには `[取り消し失敗]` と記録されます。
アクションの失敗と同じように、カットフォルダを開いて、ファイルを手で直してください。

### ログやカット情報が書き込めないとき

「ログ保存フォルダ … にアクセスできませんでした」や「ログファイル … を開けませんでした」と表示された場合は、ログフォルダに書き込めていません。
ファイルの操作は終わっていても、ログが残っていないことがあります。
フォルダが開けるか、書き込みの権限があるかを確かめてください（[共有フォルダでの運用](administration/shared-operation.ja.md) の「アクセス権」を参照）。

「カット情報フォルダ … にアクセスできませんでした」や「カット情報のファイル … に書き込めませんでした」と表示された場合は、カット情報を書き込めていません。
表示されるパスは、プロジェクト情報フォルダの `scene_info` フォルダの中です。ログフォルダと同じように、書き込みの権限を確かめてください。

### PPM がしばらく止まる

工程ごとのカットの一覧を書き換えるとき、PPM はほかの人と同時に書き換えないように、`〜_details.lock` というファイルを作ります。
ほかの PC の PPM が強制終了したなどで、このファイルが残っていると、PPM は最大で30秒ほど待ってから処理を続けます。
何度も止まる場合は、プロジェクト情報フォルダの `progress_cache` フォルダに、古い `.lock` ファイルが残っていないか確かめてください（[共有フォルダでの運用](administration/shared-operation.ja.md) を参照）。

## Google 連携がうまくいかない

| 症状 | 原因と対処 |
|---|---|
| **取り消す** ボタンが「取り消す (*)」になった | Google スプレッドシートへの書き込みに失敗しました。ログフォルダの `google_spreadsheet_cues` フォルダに残った記録で原因を確かめ、必要ならスプレッドシートを手で直します（[Google スプレッドシート連携](integrations/google-spreadsheet.ja.md) を参照）。 |
| スプレッドシートに何も書き込まれない | プロジェクト設定の **Google Apps スクリプトのURL** が空だと、このステップは飛ばされます。シートに行がないカットにも、何も書き込まれません。 |
| 「Google Chatへの通知の送信に失敗しました」と表示される | 警告に表示された原因と、ログフォルダの `google_chat/google_chat.log` を確かめます（[Google Chat 通知](integrations/google-chat.ja.md) を参照）。 |
| 終了しようとすると、書き込みや通知が終わっていないと警告される | **待つ** を押して、しばらくしてから閉じてください。**終了する** を押すと、送られていない内容は失われます（[メイン画面](using/main-window.ja.md) を参照）。 |

## よくある質問

### 間違えてアクションを実行してしまいました

灰色になった行の **取り消す** ボタンを押すと、元に戻せます。
**リスト更新** を押すと **取り消す** ボタンは消えるので、その後はファイルを手で直します（[カットに対する操作](using/scene-operations.ja.md) と [ファイルを直接扱う](concepts/working-with-files.ja.md) を参照）。

### カットを途中の工程から始めたい／前の工程に戻したい

途中の工程から始めるときは、その工程を右クリックして **この工程から始めるカットを登録する** を使います（[カットの登録](using/registering-scenes.ja.md) を参照）。
同じ工程グループの前の工程に戻すときは、工程内リテイクを使えます（[カットに対する操作](using/scene-operations.ja.md) を参照）。
キューファイルを手で置いたり、名前を変えたりして直すこともできます（[ファイルを直接扱う](concepts/working-with-files.ja.md) を参照）。

### PPM を使わずにファイルを動かしてもかまいませんか

かまいません。PPM は、ファイルの名前と場所で進捗を判断しています。
ただし、ファイルを動かした後は、工程グループの更新ボタンを押してください（[ファイルを直接扱う](concepts/working-with-files.ja.md) を参照）。

### ほかの人が変えたプロジェクト設定が、自分の PPM に反映されません

PPM は、プロジェクトのファイルを、起動したときと、プロジェクトを切り替えたときにだけ読み込みます。
PPM を起動し直してください（[共有フォルダでの運用](administration/shared-operation.ja.md) を参照）。

### ログのユーザー名が、環境設定のユーザー名と違います

ログに記録されるのは、Windows のユーザー名です。
環境設定の **ユーザー名** は、プロジェクトの設定の中の `[USER_NAME]` に使われます（[バックアップと復旧](administration/backup.ja.md) の「ログから経緯をたどる」を参照）。

### ログに英語と日本語が混ざっています

ログは、操作した人の PPM の言語で書かれます。
英語の PPM で操作した行は、`[FAILED]` や `2026 10/30 10:12:05` のように記録されます。

### 工程ごとのカットの一覧のファイルが壊れた、または消えてしまいました

工程グループの更新ボタンを押すと、キューファイルから作り直せます（[バックアップと復旧](administration/backup.ja.md) を参照）。

### PPM をアンインストールするには

展開したフォルダを削除します。
ユーザーごとの設定も消すときは、`%LOCALAPPDATA%\PPM\usersettings.ini` も削除します（[インストール](getting-started/installation.ja.md) を参照）。

## 解決しないときは

不具合と思われるときは、[不具合報告・要望](about/reporting-issues.ja.md) を参照して、報告してください。
